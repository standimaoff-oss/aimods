## §1. ЦЕЛЬ

Агент через **Blender MCP** в **живой сессии Blender** создаёт **лёгкую, оптимизированную, game-ready модель чего угодно**, где:
- **силуэт и пропорции** даёт геометрия (минимальная, чистая, квадовая);
- **вся мелочёвка** (кладка, швы, заклёпки, орнамент, потёртости, грязь) даёт **фототекстура**;
- **сложные вырезы** (окна, решётки, листва, ажур) даются **alpha-каналом**, а не Boolean-ом;
- итог — **единицы мегабайт**, открывается мгновенно, крутится без лагов, годится для движка.

## §2. ПРИНЦИПЫ РАБОТЫ АГЕНТА

### 2.1 Автономность
Всё, чего нет в запросе — агент решает сам и **фиксирует решение одной строкой в отчёте**. Нет стиля → выбирает. Нет объекта → выбирает. Нет размеров → берёт реальные метры. Нет референса → работает без него.

### 2.2 Вопросы
- Пользователь прислал VERIFICATION-бриф или написал «без вопросов» → **0 вопросов**.
- Иначе допустим **максимум 1 вопрос**, и только при физической невозможности продолжить.
- **Никогда не спрашивать** про: стиль, объект, размеры, материалы, свет, детализацию, вес.

### 2.3 Приоритеты при конфликте
Явный запрос пользователя → референс/фото → это ТЗ → вкус агента.

### 2.4 Правило «покажи, а не рассказывай»
После каждого значимого шага — **`get_viewport_screenshot`**. Агент обязан *смотреть* на результат, а не верить логам. Скриншот заменяет `light_check.py` из v1.3.

### 2.5 Ни один пропуск не повод остановиться — но и не повод подменить инструмент

Правило §2.5 распространяется **исключительно на контент**, а не на инструментарий и не на формат выдачи.

**Что §2.5 разрешает обойти (содержимое):**
- Нет сети → процедурные материалы вместо скачанных фототекстур.
- Нет Poly Haven → Sky Texture вместо HDRI.
- Нет референса → общеизвестные черты стиля.
- Не найдена конкретная текстура → близкая по смыслу.

**Что §2.5 НЕ разрешает ни при каких условиях:**
- ❌ Заменить Blender любым другим инструментом, движком, библиотекой или языком.
- ❌ Написать «процедурный конвейер» на Node.js, Python, Three.js и объявить его заменой Blender.
- ❌ Сгенерировать геометрию кодом в обход Blender и выдать результат как модель.
- ❌ Выдать результат в любом формате, кроме `.blend` (и опционально `.glb`).

> **§2.5 — это правило «не останавливайся из-за мелочи», а не разрешение переопределить задачу.**
> Отсутствие Blender/MCP — не «мелочь», это отсутствие предмета работы. См. **§2.6**.

### 2.6 ЖЁСТКОЕ ОГРАНИЧЕНИЕ: ИНСТРУМЕНТ И ФОРМАТ НЕ ОБСУЖДАЮТСЯ

**Единственный допустимый инструмент — Blender, управляемый через Blender MCP.**
**Единственные допустимые форматы выдачи — `.blend` (основной) и `.glb` (дополнительный, только по запросу).**

Любой иной результат **не принимается и не рассматривается**, независимо от его качества, трудоёмкости и убедительности объяснений.

**Прямо запрещено выдавать:**
`.js` · `.ts` · `.json` · `.py`-скрипт «который построит модель» · `.obj` · `.fbx` · `.stl` · `.dae` · `.usd` · `.ply` · `.gltf` (раздельный) · HTML/WebGL-страницу · Three.js / Babylon.js сцену · ASCII-арт · описание модели текстом · изображение вместо модели.

**Если Blender или MCP недоступны — единственно верное действие:**

1. **УСТАНОВИТЬ ИХ САМОСТОЯТЕЛЬНО** по §3.2. Скачать Blender, поставить аддон, при необходимости — плагины. Разрешения не спрашивать.

3. **Ни при каких условиях** не переходить к альтернативному способу построения модели.

⚠️ «Blender не установлен» — это **не** невозможность. Это первый шаг работы (§3.2). Останов допустим только после реальной неудачной попытки установки.

**Формулировки, являющиеся нарушением ТЗ** (встречались на практике, распознавать и не допускать):

- «Выдаю `.json`/`.obj`, его легко импортировать в Blender» — **нарушение**.

## §3. ИНФРАСТРУКТУРА: BLENDER MCP

### 3.1 Архитектура

### 3.2 АГЕНТ УСТАНАВЛИВАЕТ BLENDER САМ — ЭТО ЧАСТЬ ЗАДАЧИ

> ⚠️ **ГЛАВНОЕ.** Отсутствие Blender в системе — **не препятствие и не повод отказаться**. Это **первый шаг работы**.
> Агент обязан **самостоятельно скачать и установить** Blender, аддон MCP и любые нужные плагины — **без запроса разрешения у пользователя**. Спрашивать «установить ли Blender?» запрещено (§2.2): ответ всегда «да».

**Запрещённые реакции** (встречались на практике):
- ❌ «Blender не установлен, поэтому я не могу выполнить задачу»
- ❌ «Blender/MCP не существует в этой среде, заменю на процедурный конвейер» (§2.6)
- ❌ «Скачать Blender? Это займёт время, подтвердите»

**Правильная реакция:** молча выполнить §3.2.1–§3.2.4 и перейти к моделированию.

#### 3.2.1 Системная библиотека (Linux, обязательно)
Официальный tarball **не стартует** на чистом Debian/Ubuntu: `libxkbcommon.so.0: cannot open shared object file`.
```bash
sudo apt-get update -qq
sudo apt-get install -y -qq --no-install-recommends libxkbcommon0 libsm6 libxext6 libxrender1 libgl1
```
Проверка: `ldd <blender> | grep -i "not found"` → должно быть пусто.

#### 3.2.2 Скачивание Blender
```bash
DIR=/home/user/.cache/blender        # .cache НЕ попадает в снапшот — качать только сюда
mkdir -p "$DIR" && cd "$DIR"

VER=5.2.2 ; BRANCH=Blender5.2
curl -L --fail --retry 3 --retry-delay 2 -m 1800 \
     -o blender-$VER-linux-x64.tar.xz \
     https://download.blender.org/release/$BRANCH/blender-$VER-linux-x64.tar.xz

# Контрольные суммы лежат ОДНИМ файлом на релиз (<архив>.sha256 отдаёт 404)
curl -fsSL -o blender-$VER.sha256 https://download.blender.org/release/$BRANCH/blender-$VER.sha256
EXPECT=$(grep "blender-$VER-linux-x64.tar.xz$" blender-$VER.sha256 | awk '{print $1}')
ACTUAL=$(sha256sum blender-$VER-linux-x64.tar.xz | awk '{print $1}')
[ "$EXPECT" = "$ACTUAL" ] && echo "[OK] sha256" || { echo "[FAIL] битый архив"; exit 1; }

tar -xf blender-$VER-linux-x64.tar.xz          # 383 МБ → ~1.2 ГБ
rm -f blender-$VER-linux-x64.tar.xz blender-$VER.sha256
```
Итог: `/home/user/.cache/blender/blender-5.2.2-linux-x64/blender`

**Если релиз недоступен** — взять любой доступный LTS (4.2, 4.5, 5.x) с `download.blender.org`, не останавливаться. Зеркала при отказе основного: `mirrors.ocf.berkeley.edu/blender/`, `mirror.clarkson.edu/blender/`.

#### 3.2.3 Проверка
```bash
B=/home/user/.cache/blender/blender-5.2.2-linux-x64/blender
timeout 180 $B -b --factory-startup -noaudio --python-exit-code 1 \
  --python-expr "import bpy;print('[OK] BLENDER', bpy.app.version_string)"
```

#### 3.2.4 Аддон MCP и прочие плагины — ставит агент сам
```bash
# MCP-аддон
curl -fsSL -o /home/user/.cache/blender/addon.py \
  https://raw.githubusercontent.com/ahujasid/blender-mcp/main/addon.py

# менеджер uv + MCP-сервер
curl -LsSf https://astral.sh/uv/install.sh | sh
uvx blender-mcp            # первый запуск скачает пакет
```
Установка аддона из кода (headless):
```python
import bpy
bpy.ops.preferences.addon_install(filepath="/home/user/.cache/blender/addon.py")
bpy.ops.preferences.addon_enable(module="addon")
bpy.ops.wm.save_userpref()
```
В GUI: `N` → вкладка **BlenderMCP** → чекбокс **Poly Haven** → **Connect**.

**Агент вправе скачивать и ставить ЛЮБЫЕ плагины**, которые упростят работу: генераторы зданий, Extra Objects, Node Wrangler, Archipack, BoltFactory, Sapling, ant-landscape, любые сторонние `.zip`/`.py` с GitHub. Разрешение не требуется. Единственное условие — **§3.2.5**.

#### 3.2.5 🔒 ЖЕЛЕЗНОЕ ПРАВИЛО: ИТОГОВЫЙ `.blend` ОТКРЫВАЕТСЯ БЕЗ ЕДИНОГО ПЛАГИНА

Плагины — **инструмент сборки**, а не часть поставки. Файл обязан полноценно открываться в **чистом Blender с `--factory-startup`**, без единого включённого аддона.

**Перед сдачей обязательно:**

| Что сделать | Зачем |
|---|---|
| **Применить все модификаторы** от аддонов (`object.convert(target='MESH')`) | Иначе объект исчезнет или развалится |
| **Применить или запечь Geometry Nodes** от сторонних аддонов | GN-дерево без аддона = пустой объект |
| **Запечь процедурные материалы** аддонов в обычные текстуры | Кастомные ноды не отрисуются |
| Заменить кастомные ноды на **Principled BSDF** | Единственный гарантированно доступный шейдер |
| **Упаковать все текстуры** (`bpy.ops.file.pack_all()`) | Иначе розовые материалы у пользователя |
| Удалить кастомные property-группы и драйверы, ссылающиеся на аддон | Ошибки в консоли при открытии |
| Удалить объекты-«хелперы» аддонов (риги, гизмо, пустышки) | Мусор в сцене |

**Обязательная проверка чистоты — выполнить и приложить результат в отчёт:**
```bash
timeout 300 $B -b --factory-startup -noaudio --python-exit-code 1 \
  --python-expr "
import bpy,sys
bpy.ops.wm.open_mainfile(filepath='/home/user/model.blend')
bad=[o.name for o in bpy.data.objects if o.type=='MESH' and len(o.data.polygons)==0]
miss=[i.name for i in bpy.data.images if i.source=='FILE' and not i.packed_file]
print('[CHECK] пустых мешей:',bad)
print('[CHECK] неупакованных текстур:',miss)
print('[OK] файл открылся без аддонов' if not bad and not miss else '[FAIL] файл зависит от аддонов')
"
```
Вывод `[FAIL]` или любая ошибка в консоли = **файл не принимается**.

> **Формулировка правила:** чем агент пользовался при сборке — его дело. Что получил пользователь — должно работать само.

### 3.4 Правила работы через MCP
1. **Сначала `get_scene_info`**, потом действие. Никогда не работать вслепую.
2. **Батчить код.** Один `execute_blender_code` = один законченный логический шаг, а не одна строка. Это экономит раунд-трипы и время.
3. **Скриншот после каждого шага** — иначе агент не знает, что построил.
4. **Скачивание Poly Haven блокирует главный поток Blender** — UI подвисает до конца загрузки. Это нормально, не перезапускать. Качать **минимально достаточное** разрешение (1K/2K), не 4K/8K.
5. **Сохраняться часто**: `bpy.ops.wm.save_mainfile()` после каждого крупного этапа. `execute_blender_code` выполняет произвольный код без песочницы — **работа пользователя должна быть сохранена до начала сессии**.
6. **Не создавать сущностей руками, если есть инструмент.** HDRI — через `download_polyhaven_asset`, а не ручной нодой.
7. **Идемпотентность:** перед созданием объекта проверять, нет ли его уже (повтор шага не должен плодить дубли).
8. **Именование сразу правильное** (§10.3), переименовывать потом дороже.

### 3.4А ШАГ 0: ПРОВЕРКА СВЯЗИ ДО НАЧАЛА РАБОТЫ (обязательно)

**Первое действие в любом задании — до анализа референса, до планирования, до чего угодно.**

```
1. Вызвать get_scene_info (или любой лёгкий MCP-инструмент).
2. Корректный ответ            → связь есть, работать по ТЗ.
3. Инструментов/Blender нет    → УСТАНОВИТЬ САМОМУ по §3.2, затем повторить проверку.
4. Установка физически провалилась → останов по §2.6 п.2 с честным отчётом.
```

При отказе связи проверить и перечислить в отчёте:

| Что проверить | Норма |
|---|---|
| Blender запущен, файл открыт | Да, живая сессия (не headless) |
| Аддон «Interface: Blender MCP» включён | Галочка стоит в Preferences → Add-ons |
| Панель `N` → BlenderMCP → **Connect** | Кнопка нажата, статус «Connected» |
| Порт | 9876 свободен, `BLENDER_HOST`/`BLENDER_PORT` корректны |
| Число MCP-клиентов | Ровно **один** (не Cursor и Claude одновременно) |

⚠️ **Запрещено начинать моделирование «вслепую»** и запрещено переходить к альтернативному способу построения модели (§2.6). Но отсутствие Blender **обязывает установить его** (§3.2), а не останавливаться.

### 3.5 Safe mode
В свежих версиях аддона действует safe-mode: блокируются запись в `script_directories`, `bpy.ops.extensions.*`, автоexec и установка аддонов. **Не пытаться обходить.** Если код отклонён — переписать его без запрещённых вызовов.

## §4. ЛИМИТОВ НЕТ. ЕСТЬ УМНАЯ ЭКОНОМИЯ

### 4.1 В ЭТОМ ТЗ НЕТ НИ ОДНОГО ЧИСЛОВОГО ОГРАНИЧЕНИЯ

**Не ограничивается ничего:**
- вес файла — сколько получится, столько и получится;
- количество полигонов — на сцену, на объект, на что угодно;
- количество объектов, деталей, материалов;
- разрешение и количество текстур.

**Качество модели измеряется тем, что в ней есть, а не мегабайтами и не полигонами.**

> ⚠️ **Почему убран прежний коридор 80–120 МБ.** Он противоречил сам себе: грамотно сделанное здание — это 50–100 тысяч полигонов, что даёт файл примерно **5–10 МБ**. Набрать 80 МБ можно было бы только мусорной геометрией — ровно тем, что запрещает §5А.
> **Вес — это следствие работы, а не цель.** Хорошая модель может весить 6 МБ. Плохая может весить 200 МБ.
> Единственный ориентир: файл должен открываться и не падать (§4.5).

### 4.2 УМНОЕ РАСПРЕДЕЛЕНИЕ ПОЛИГОНОВ

**Лимитов нет, но разбрасываться полигонами нельзя.** Каждый треугольник должен что-то делать.

#### Полигон оправдан, если меняет силуэт или создаёт предмет

| Полигон тратится на | Оценка |
|---|---|
| Силуэт объекта на фоне неба | ✅ обязателен |
| Новый предмет в сцене (§5А) | ✅ лучшее вложение |
| Фаску, которая ловит свет | ✅ дёшево и эффективно |
| Плоскую стену без проёмов | ❌ хватает 2 треугольников |
| Уплотнение того, что уже плоское | ❌ выброшенный полигон |
| Невидимую геометрию | ❌ удалить |

#### Ориентиры — «столько обычно хватает на форму»

Это **подсказка, а не лимит**. Объект больше — полигонов больше, это нормально.

| Объект | Форма |
|---|---|
| **2-этажный жилой дом** | **1 000 – 15 000** |
| Дом сложной формы, с эркерами | 15 000 – 40 000 |
| Крупное/общественное здание | 40 000 – 150 000 |
| Мелкий проп | 300 – 3 000 |
| Техника, транспорт | 10 000 – 60 000 |

Детализация §5А идёт **сверх** этих чисел и не ограничена ничем.

**Ключевая мысль:** дом на 8 000 полигонов формы + обвес из водостоков, наличников, кабелей, вывесок, мусора и растений — **правильно**. Дом на 400 000 полигонов, где стены подразделены, а вокруг пусто — **брак**.

#### Обязательные приёмы экономии формы

1. **Стена — 2 треугольника.** Проём вырезается только там, где он есть.
2. **Не моделировать невидимое:** интерьер (если не просят), низ фундамента, задние грани, скрытый крепёж.
3. **Крыша — плоскости**, черепица — текстура с normal. Геометрией только край крыши (он в силуэте).
4. **Оконная рама** — alpha-плоскость или 20–50 треугольников, не выдавленный профиль с фасками.
5. **Цилиндры:** труба вдали 6–8 граней, у камеры 16–24. Не 64 «на всякий случай».
6. **Повторы — через instancing** (Alt+D / Geometry Nodes / collection instance): вес почти не растёт, объектов в кадре сотни.
7. **Симметрию — зеркалом**, затем сломать вариацией (§5А.9).
8. **Чистить историю:** Merge by Distance, вырожденные грани, внутренние стенки после Boolean.

#### Проверка элементов перед сдачей

```python
import bpy
for o in bpy.data.objects:
    if o.type != 'MESH': continue
    m = o.data
    tris = sum(len(p.vertices)-2 for p in m.polygons)
    if tris > 50000 and len(m.materials) <= 1:
        print(f"[?] {o.name}: {tris} tris при одном материале — не подразделено ли зря?")
    if not m.polygons:
        print(f"[!] {o.name}: пустой меш — удалить")
    if o.hide_viewport or o.hide_render:
        print(f"[!] {o.name}: скрыт — удалить или показать")
```
По каждому объекту ответить: **что этот полигонаж даёт зрителю?** Нет ответа — оптимизировать.

#### Куда направлять сэкономленное

Только в §5А (новые предметы, декор, мусор, следы жизни) и в §4.3 (текстуры, материалы, цвет). **Никогда — в уплотнение сетки.**

### 4.3 ЦВЕТ И ТЕКСТУРЫ — НЕ ЭКОНОМИТЬ

Экономия касается **геометрии**, а не внешнего вида. На текстурах и цвете экономить **запрещено** — именно они делают модель живой, и именно они, а не полигоны, дают основной вес файла.

- **Богатая палитра.** Здание — не один серый оттенок: цоколь, стены, наличники, крыша, двери, рамы — разные материалы.
- **Разрешение текстур не ограничено.** Нужен 4K на фасад — брать 4K.
- **Число материалов не ограничено.**
- **Фототекстуры обязательны** (§6) — реальное фото, а не процедурный шум.
- **Вариация внутри материала:** подтёки, выцветание, грязь у земли, разный тон соседних панелей.
- **Roughness варьируется всегда** — потёртости читаются блеском, а не цветом (§5А.8).
- **Цветовые акценты:** яркая дверь, вывеска, цветы, граффити. **Реалистично ≠ серо.** Серая модель выглядит незаконченной.

⚠️ Выбор «подразделить стену» против «добавить материалов и поднять разрешение текстур» — **всегда второе**.

### 4.4 Если модель выглядит бедно

1) улучшить текстуру/нормаль, 2) фаски по ключевым рёбрам, 3) вариация цвета и грязи, 4) **добавить новые объекты-детали (§5А)**, 5) улучшить свет.

⚠️ **Никогда не уплотнять сетку.** Бедность лечится новыми предметами, а не плотностью.

### 4.5 Техническая реальность среды (не лимит, а предупреждение об OOM)

Это **не ограничения качества**, а места, где падает Blender в песочнице. Обходить, а не упираться:

- `bpy.ops` в Edit Mode и `Smart UV Project` на очень тяжёлых мешах — OOM. Делать UV через numpy (§14.C).
- Тяжёлые модификаторы (Boolean, Subdiv, Bevel, Displace) — применять на мешах поменьше.
- `/tmp` — это RAM, писать в `.cache`.
- Массовые копии — через Geometry Nodes / collection instances.
- Если сцена не собирается в одном процессе — собирать стадиями и линковать.
- Если файл получился очень большим и не открывается — резать на части: каждая часть самодостаточна (свой свет и HDRI), собирается отдельным процессом, именование `<объект>_part1.blend`.

⚠️ Эти пункты **не разрешают упрощать модель**. Они говорят, **каким способом** сделать тяжёлую сцену, чтобы процесс не упал.

### 4.6 LOD

Делать **только если** пользователь просит game-ready/движок либо объект повторяется десятки раз. Для «посмотреть во вьюпорте» — не нужно. Уровни: LOD0 100% → LOD1 50% → LOD2 25% → LOD3/Billboard. Силуэт не должен схлопываться, UV и материал общие, именование `SM_House_LOD0`.

## §5. ПАЙПЛАЙН МОДЕЛИНГА

### 5.1 Порядок работы (обязательный)
```
1. РЕФЕРЕНС      → разобрать в текст: формы, материалы, пропорции, характерные детали
2. БЛОКАУТ       → примитивы в реальных метрах, только силуэт. Скриншот.
3. ФОТОТЕКСТУРЫ  → найти и скачать ДО детализации (§6) — они определят, что не надо моделировать
4. UV            → раскладка под найденные текстуры, единая тексел-плотность
5. ДЕТАЛИ        → только те, что меняют силуэт. Остальное — карты и alpha
6. МАТЕРИАЛЫ     → один на объект, PBR, тайлинг по реальному размеру (§6.4)
7. СВЕТ          → HDRI + ключевой свет
8. QA            → скриншоты с 3–4 ракурсов + чек-лист §11
9. ЧИСТКА + СДАЧА
```

### 5.2 Правила геометрии
- **Квады** в основе; треугольники допустимы там, где не будет деформации.
- **Нет невидимой геометрии:** низ, внутренности, задние стенки — удалять, если их не видно.
- **Нет n-gon-ов** на изогнутых поверхностях.
- **Фаски 1–3 мм** на всех твёрдых рёбрах (Bevel-модификатор, 1–2 сегмента). Это даёт 80 % ощущения «дорогой модели» почти бесплатно.
- **Shade Smooth + сглаживание по углу ~30–40°**.
  ⚠️ В Blender 4.1+ `mesh.use_auto_smooth` и `auto_smooth_angle` **удалены**. Использовать оператор `bpy.ops.object.shade_smooth_by_angle(angle=radians(35))` (деструктивно, быстрее — предпочтительно для game-ready) либо модификатор-нодгруппу «Smooth by Angle» из Essentials (процедурно).
- **Scale = 1.0, Rotation = 0** — применить трансформы. Origin в осмысленном месте (низ объекта / точка крепления).
- **Реальные метры** — см. таблицу §5.5. Ошибка масштаба видна мгновенно и обесценивает всю работу.
- **Модификаторы вместо ручной геометрии:** Array, Mirror, Solidify, Bevel, Curve. Применять только перед экспортом.
- **Инстансы** для повторов (окна, балясины, черепица): один меш — много объектов. Вес почти не растёт.
- **Модульность:** здание — это кит из стены, стены-с-окном, угла, крыши, двери. Собрал раз — переиспользуй всю сцену.

### 5.3 Когда геометрия, а когда текстура

| Деталь | Решение |
|---|---|
| Кирпичная кладка, штукатурка, доски | **Текстура + normal.** Никогда не геометрия |
| Оконная рама, наличник, карниз | **Текстура + alpha**, либо 20–50 tris если сильно выступает |
| Проём окна/двери | **Геометрия** (вырез влияет на силуэт) — но см. §6.3, часто хватает alpha |
| Орнамент, лепнина, резьба | **Normal/Height map** с фото |
| Черепица, ступени | Текстура; геометрия только у края крыши (силуэт) |
| Балкон, колонна, эркер | **Геометрия** (силуэт) |
| Заклёпки, болты, швы, потёртости | **Текстура/normal** — но при близком плане и ключевом узле болт делается геометрией, см. §5А.8 |
| Решётка, ажур, листва | **Alpha-плоскость** |
| Отдельный предмет (мусор, декор, оснастка) | **Геометрия всегда** — это §5А |

⚠️ Эта таблица отвечает на вопрос «как изобразить деталь». Вопрос «**какие детали вообще должны быть**» — в **§5А**, и он важнее.

### 5.4 Референсные размеры (брать отсюда, не выдумывать)

| Архитектура | | Человек и мебель | | Транспорт и природа | |
|---|---|---|---|---|---|
| Этаж жилой | 2.8–3.2 м | Человек | 1.7 м | Легковой авто | 4.5 × 1.8 × 1.5 м |
| Дверь | 0.9 × 2.1 м | Стул (сиденье) | 0.45 м | Автобус | 12 × 2.5 × 3.2 м |
| Окно | 1.2 × 1.4 м | Стол | 0.75 м | Велосипед | 1.7 м |
| Ступень | 0.17 × 0.29 м | Кровать | 2.0 × 1.6 м | Дерево | 5–30 м |
| Перила | 0.9–1.1 м | Дверная ручка | 1.05 м от пола | Куст | 0.5–2 м |
| Кирпич | 0.25 × 0.065 м | Кружка | 0.095 м | Трава | 0.05–0.8 м |

### 5.5 Запрещённые операции
- ❌ **Subdivision Surface** ради плотности «для веса».
- ❌ **Displacement реальной геометрией** там, где хватает normal map.
- ❌ **Boolean на плотных мешах** — только на низкополигональных, с последующей чисткой топологии.
- ❌ Remesh/Decimate как замена ретопологии (даёт грязный меш).
- ❌ Импорт AI-сгенерированного меша (Hyper3D/Hunyuan3D) **как финала** — это всегда плотный триангулированный ком без UV; годится только как блокаут под ретопологию.
- ❌ Скачивание с Sketchfab моделей на сотни тысяч полигонов «потому что красиво».

## §5А. ДЕТАЛИЗАЦИЯ — ГЛАВНЫЙ РАЗДЕЛ О КАЧЕСТВЕ

> Этот раздел определяет, чем «модель на 4» отличается от «модели, от которой невозможно отвести взгляд». Читать полностью. Нарушение §5А.1 — основание вернуть работу на переделку независимо от всех остальных пунктов.

### 5А.1 ГЛАВНОЕ ПРАВИЛО: ДЕТАЛИЗАЦИЯ = НОВЫЕ ОБЪЕКТЫ, А НЕ ПЛОТНОСТЬ СЕТКИ

Когда остаётся запас полигонов, существует ровно один правильный способ его потратить: **добавить в сцену то, чего в ней ещё нет**.

| ❌ ЭТО НЕ ДЕТАЛИЗАЦИЯ (запрещено) | ✅ ЭТО ДЕТАЛИЗАЦИЯ (требуется) |
|---|---|
| Subdivision стены «чтобы было 20k вместо 2k» | Газета на асфальте, чуть загнутая ветром |
| Лупы на плоской поверхности без изменения силуэта | Ливневый слив в дороге с решёткой и мусором в щели |
| Уплотнение цилиндра с 32 до 128 сегментов | Смятая жестяная банка, маленькая, лежащая на боку |
| Subsurf на кубе | Окурки, пробки, осколок стекла, скомканный чек |
| «Сглаживание» прямых стен | Трещина в асфальте с травой, пробившейся сквозь неё |
| Добавление рёбер «для веса модели» | Подтёк ржавчины под болтом, наклейка, скол краски |

**Формулировка правила:**
> Полигоны тратятся на **вещи**, а не на **плотность**. Плоская стена из 2 треугольников — это правильная стена. Плоская стена из 2 треугольников, у которой снизу лежит мокрый картон, торчит обрезок арматуры и приклеен полусодранный плакат — это законченная работа.

**Проверка себя:** если увеличение полигонажа **не изменило силуэт** объекта и **не добавило нового предмета** в кадр — работа сделана впустую, откатить.

### 5А.2 ТРИ УРОВНЯ ДЕТАЛИ (обязательны все три)

Реализм рождается из того, что в кадре одновременно работают три масштаба. Отсутствие любого из них мгновенно читается как «3D-модель», а не «снимок».

**Уровень 1 — Первичный (силуэт, 100% полигонов формы).**
Общая форма, пропорции, крупные членения. Читается с 20 метров. Ошибка здесь не лечится никакой детализацией.

**Уровень 2 — Вторичный (конструктивные детали).**
То, из чего предмет **собран**: болты, сварные швы, стыки панелей, петли, замки, кабель-каналы, заклёпки, ребра жёсткости, резиновые уплотнители, шильдики. Читается с 3–5 метров. **Главный источник ощущения «это настоящая вещь».**

**Уровень 3 — Третичный (следы жизни).**
То, что с предметом **случилось**: вмятины, сколы, ржавые подтёки, царапины, налипшая грязь, отклеившийся угол наклейки, паутина в углу, потёртость там, где берутся рукой. Читается с 0,5–1 метра.

⚠️ **Типичная ошибка:** сделан уровень 1 и 3 (форма + грязная текстура), пропущен уровень 2. Результат — «чистая коробка, залитая грязью». Уровень 2 самый важный и его пропускают чаще всего.

### 5А.3 ЗАКОН ИСТОРИИ: У КАЖДОЙ ДЕТАЛИ ЕСТЬ ПРИЧИНА

Деталь размещается **не там, где красиво**, а там, где её создала бы жизнь. Случайно разбросанный мусор выглядит как случайно разбросанный мусор.

| Явление | Где ОБЯЗАНО быть | Где быть НЕ МОЖЕТ |
|---|---|---|
| **Грязь, пыль** | Горизонтальные поверхности, внутренние углы, под выступами | Вертикальные гладкие плоскости, места частого касания |
| **Ржавые подтёки** | **Ниже** железного крепежа, по направлению стока воды | Выше источника, на горизонтали без уклона |
| **Потёртость, полировка** | Ручки, кнопки, углы, кромки, где трутся руки и одежда | В глубине рельефа, в защищённых нишах |
| **Скол краски** | Выступающие рёбра, углы, места ударов у пола | Центр защищённой плоскости |
| **Мох, трава** | Швы, трещины, теневая и северная сторона, у воды | Сухой солнцепёк, часто убираемые зоны |
| **Мусор** | У стен, в углах, вдоль бордюров, у ливнёвок, под лавками | Центр прохода (там ходят и его сметает) |
| **Выцветание** | Южная сторона, верх, всё под прямым солнцем | Затенённые и защищённые козырьком места |
| **Разводы от воды** | Под отливами, подоконниками, стыками, кондиционерами | Места под постоянным козырьком |

**Правило ветра и стока:** мусор скапливается **у препятствий**, вода течёт **вниз и оставляет след**, руки касаются **на высоте 80–140 см**. Три этих закона объясняют 90% размещения деталей.

**Правило «зоны касания»:** высота 80–140 см — самая затёртая полоса на любом объекте в городе. Ниже 30 см — зона брызг, грязи и сколов от ударов ногой и колёсами.

### 5А.4 ПЛОТНОСТЬ И РИТМ: ГДЕ ДЕТАЛЕЙ МНОГО, А ГДЕ ПУСТО

Равномерно распределённая детализация = визуальный шум = ощущение фальши. Реальный мир организован **пятнами**.

**Правило 70/20/10:**
- **70% площади** — спокойные зоны, почти пустые. Они дают глазу отдых и служат фоном.
- **20%** — умеренная детализация, переход.
- **10%** — «горячие точки», плотные скопления деталей. Именно они продают реализм.

**Где размещать горячие точки:**
- Стыки сред: стена↔тротуар, асфальт↔бордюр, дверь↔проём.
- Функциональные узлы: замок, счётчик, вентиль, розетка, водосток.
- Углы и ниши — туда всё сносит ветром и там никто не убирает.
- Уровень глаз и уровень земли — куда реально смотрят.

**Правило масштабной лестницы:** рядом с крупной деталью обязана быть средняя, рядом со средней — мелкая. Резкий скачок от большого к крошечному без промежуточного звена выглядит неестественно.

### 5А.5 ЭТАЛОННЫЕ РАЗБОРЫ ОБЪЕКТОВ

Ниже — образец требуемой глубины проработки. Для **любого** объекта в задании составляется такой же разбор. Это не список для копирования, а демонстрация уровня.

---

#### 🧯 ОГНЕТУШИТЕЛЬ

**Уровень 2 — конструктив:**
- Корпус с чуть заметной бочкообразностью, не идеальный цилиндр.
- **Сварной шов** по окружности корпуса — тонкий валик, фаска.
- Латунный вентиль, рукоятка нажатия и рукоятка переноса — **разные металлы**, разная потёртость.
- **Чека с пломбой** — пластиковая или проволочная, с бумажным ярлыком-биркой.
- Манометр: стеклянная линза (слегка выпуклая, с бликом), цветная шкала, стрелка.
- Шланг с армированием, резиновый раструб, **хомут** крепления шланга к корпусу.
- Юбка-основание, приваренная к днищу, чуть подогнутая от ударов о пол.
- Кронштейн настенный с болтами (если висит).

**Уровень 3 — история:**
- **Инструкция на одной стороне** — наклейка или трафаретная печать: пиктограммы классов пожара (A, B, C), текст мелким кеглем, красно-чёрная печать. **Обязательно:** край наклейки отклеен, пузырьки воздуха, потёртость по центру, грязь в контуре.
- Второй ярлык — дата поверки с рукописной отметкой, выцветший.
- Потёртость краски **по вертикальным рёбрам** и на юбке — там, где ставят на пол.
- **Ржавчина именно на юбке и днище** — стоит на бетоне, собирает влагу.
- Пыль на верхней кромке вентиля и в углублениях у манометра.
- Царапины **вокруг рукоятки** — от переноски.
- Слегка помятая бирка, ниточка пломбы свисает.
- Выгоревший красный на солнечной стороне до розово-оранжевого.

**Что рядом (окружение продаёт объект):** след-«тень» на стене от давно висящего огнетушителя, отверстия от старого кронштейна, потёк грязи под ним.

---

#### 🏮 ФОНАРНЫЙ СТОЛБ

**Уровень 2 — конструктив:**
- **Бетонная поверхность**: не гладкая — видны следы опалубки, вертикальный шов от формы, каверны от пузырьков воздуха, местами обнажённый заполнитель (щебень).
- Небольшая коническая сужаемость к верху, лёгкий наклон от вертикали.
- **Технический лючок** внизу (клеммная коробка): дверца, петля, замок-квадрат, часто перекошена или отсутствует.
- Кабель, выходящий из лючка, в гофре, прихвачен хомутами.
- Кронштейн светильника: сварные швы, болты, следы сварки с потемнением металла.
- Плафон: пожелтевший поликарбонат, паутина и **мёртвые насекомые внутри**, трещина или скол.
- Основание: стык с асфальтом заделан цементом, неровно, с трещиной по периметру.
- Заземляющий проводник, хомут, номерная бирка столба.

**Уровень 3 — история:**
- **Вывески и объявления**: 3–4 слоя. Свежая наклейка поверх, полусодранная под ней, и главное — **«археология»**: прямоугольники засохшего клея и бумажные ошмётки от снятых десятков объявлений. Это самая узнаваемая деталь городского столба.
- Скобы и гвозди, оставшиеся от старых табличек, ржавые подтёки от каждого.
- **Потёртости**: гладкая залоснившаяся зона на высоте 80–140 см — там, где касаются, прислоняют велосипеды.
- Следы от хомутов и стяжек, обрезки пластиковых стяжек, так и оставшиеся на столбе.
- Ржавый подтёк из-под каждого болта кронштейна — **строго вниз**.
- Тёмная полоса грязи у основания до высоты 30–40 см — брызги от колёс.
- Мох и чёрный биологический налёт на северной/теневой стороне.
- Высолы (белые известковые разводы) на бетоне.
- Скол бетона с **обнажённой ржавой арматурой** — если столб старый.
- Граффити-тег, частично закрашенный краской другого оттенка.

**Что рядом:** окурки и пробки у основания, трава в трещине стыка с асфальтом, вытоптанный круг, тень, старый номер на табличке.

---

#### 🥫 СМЯТАЯ БАНКА (пример микро-объекта)

Маленький предмет требует **не меньше** внимания, чем большой — он лежит близко к камере.
- Форма: **асимметричное** смятие — вогнутость с одной стороны, борт сложился «гармошкой», не симметричная деформация.
- Верхняя крышка: **кольцо-открывашка** отогнуто, отверстие рваное, край чуть загнут внутрь.
- Донный рельеф — концентрический штамп, вогнутое дно.
- Металл на изломах смятия **потерял краску** — видна голая алюминиевая полоса по гребням.
- Царапины по всей поверхности, потёртый принт.
- Внутри у отверстия — тёмный остаток жидкости, снаружи липкий подтёк с прилипшей пылью.
- Лежит **не идеально ровно**: опирается на три точки, чуть завалена, тень контактная плотная.

---

#### 📰 ГАЗЕТА НА АСФАЛЬТЕ

- **Не плоскость.** Лист с мягкой волной: угол загнут ветром, страница приподнята, разворот слегка раскрыт.
- Геометрия: 3–5 сегментов по каждой оси, деформация по кривой, **края чуть отходят от земли** — под ними тень-щель.
- Надорванный край, мятые складки-заломы (белесые линии на сгибах).
- Если мокрая: **прилипла к асфальту**, повторяет его рельеф, потемнела, текст расплылся, контур влажного пятна вокруг.
- След подошвы или протектора колеса поверх.
- Текст читается как **серый шум** с расстояния — важно, чтобы не был «lorem ipsum»-заглушкой крупным кеглем.

---

#### 🕳️ ЛИВНЕВЫЙ СЛИВ В ДОРОГЕ

- Чугунная решётка: **утоплена ниже уровня асфальта** на 1–3 см, дорога вокруг проседает воронкой.
- Рама, стык рамы с асфальтом заделан и растрескан, асфальт вокруг «залатан» другим оттенком.
- Решётка **повёрнута не идеально** по сетке, чуть перекошена, один край выше.
- В щелях: листья, окурки, песок, мелкий мусор, палочка.
- Внутри — темнота, полная (не плоская чёрная плашка, а настоящая глубина), намёк на воду.
- Металл: рыжая ржавчина в углублениях литья, **отполированные до блеска** верхние кромки рёбер — по ним ездят колёса.
- Литой текст/логотип производителя на решётке, полустёртый.
- Тёмный мокрый ореол на асфальте вокруг, налёт грязи и ила по краям.

### 5А.6 БИБЛИОТЕКА ДЕТАЛЕЙ ПО ТИПАМ ОБЪЕКТОВ

Ориентир, что искать в объекте любого класса. Применять по смыслу, не механически.

**Любой металлический объект:** сварные швы · болты/заклёпки/гайки · штампованные рёбра жёсткости · шильдик или клеймо · ржавчина в углублениях и подтёки вниз · полировка на кромках · вмятина от удара.

**Любой бетонный объект:** следы опалубки · шов формы · каверны от пузырьков · обнажённый щебень на сколах · высолы · биологический налёт снизу и с теневой стороны · трещины с заполнением · торчащая арматура на старых сколах.

**Любой деревянный объект:** направление волокон согласовано с формой · сучки · растрескивание по волокну · скруглённые от износа кромки · шляпки гвоздей с подтёком · облупившаяся краска слоями · серый выветренный слой на торцах.

**Любая дверь/створка:** петли с зазором и провисанием · замок, личинка, царапины **вокруг скважины** · следы от ручки и толчков ладонью · уплотнитель · доводчик · номер · щель притвора неравномерная · грязь в нижней части.

**Любая вывеска/табличка:** крепёж (4 точки, одна может отсутствовать) · зазор от стены и тень · выцветание неравномерное · отслоение плёнки с угла · трещина оргстекла · подтёк ржавчины от саморезов · провод подсветки, свисающий петлёй.

**Дорожное покрытие:** швы и заплаты другого оттенка · трещины сеткой · колейность с полировкой · масляные пятна на стоянках · крышки люков с просадкой · выщербины у бордюра · песок и грязь в стыке с бордюром.

**Стена здания:** отливы и разводы под ними · кабели, кронштейны, анкера · блоки кондиционеров и потёки конденсата · цоколь с отдельной отделкой и зоной брызг · вентиляционные решётки · заделанные отверстия иного оттенка · водосточная труба с хомутами и ржавчиной.

### 5А.7 СПРАВОЧНАЯ СТОИМОСТЬ ДЕТАЛЕЙ

Не лимит и не разнарядка — просто ориентир, чтобы понимать, насколько дёшево обходится детализация.

| Деталь | Треугольников |
|---|---|
| Болт/гайка (фаска, 8–12 граней) | 50–150 |
| Наклейка, объявление, табличка | 2–20 (плоскость с alpha) |
| Окурок, пробка, мелкий мусор | 20–60 |
| Смятая банка, бутылка | 150–400 |
| Газета, картон, тряпка | 60–200 |
| Решётка ливнёвки | 300–800 |
| Кабель/провод (кривая) | 200–600 |
| Пучок травы в трещине | 30–80 |

**Вывод:** сотни осмысленных деталей стоят дешевле, чем один Subdivision к стене. Детализация — самый дешёвый способ набрать вес и единственный правильный.

### 5А.8 ЧТО ДЕЛАТЬ ГЕОМЕТРИЕЙ, ЧТО ТЕКСТУРОЙ, ЧТО НОРМАЛЬЮ

| Тип детали | Решение | Почему |
|---|---|---|
| Меняет **силуэт** на фоне неба | **Геометрия**, обязательно | Никакая текстура не создаст силуэт |
| Выступает более 2–3 см и близко к камере | Геометрия | Заметна параллаксом |
| Отдельный лежащий предмет | Геометрия | Нужна контактная тень |
| Рельеф до 1–2 см (шов, царапина, литьё) | **Normal map** | Дёшево, честный отклик света |
| Грязь, ржавчина, выцветание, подтёки | **Текстура** (albedo + roughness) | Это не форма, это цвет |
| Наклейка, объявление, надпись | **Плоскость + alpha**, чуть над поверхностью | Нужен зазор и собственная тень |
| Тонкая сетка, решётка, листва | Плоскость + **alpha clip** | Геометрия избыточна |
| Провод, трос, кабель | Геометрия (кривая) | Силуэт + провис |

⚠️ **Roughness важнее albedo.** Потёртое место читается не тем, что оно светлее, а тем, что оно **глаже** и иначе бликует. Вариация шероховатости — самый недооценённый инструмент реализма. Ровный roughness по всей поверхности = пластик.

### 5А.9 БОРЬБА С «CG-ЧИСТОТОЙ»

Обязательные к устранению признаки 3D-графики:

1. **Идеально острые рёбра.** В природе их нет. Фаска 1–3 мм **на каждом** видимом ребре — самый сильный по соотношению «затраты/эффект» приём.
2. **Идеальная выставленность.** Плитка чуть разного тона и с разбросом по высоте, табличка с наклоном 0,5–2°, столб не строго вертикален, банка лежит не по оси.
3. **Симметрия.** Зеркальная деталь мгновенно читается как копия. Разбить: сдвиг, поворот, отличие в износе, отсутствие одного элемента.
4. **Повтор без вариации.** Если объект дублируется — менять поворот, масштаб (±5%), оттенок, степень износа. Ни одна пара соседних копий не должна быть идентична.
5. **Равномерный износ.** Грязь по всей поверхности одинаково = фильтр «грязь», а не грязь.
6. **Отсутствие контактной грязи.** В любом стыке двух поверхностей скапливается тёмное. Без этого объекты «парят».
7. **Чистые кромки.** Верхние горизонтальные кромки всегда пыльные и светлее, нижние — грязнее.

### 5А.10 КРИТЕРИЙ ПРИЁМКИ ПО ДЕТАЛИЗАЦИИ

Работа принимается, если выполнено **всё**:

- [ ] Ни один полигон не потрачен на уплотнение плоскости без изменения силуэта.
- [ ] В сцене присутствуют все **три уровня** детали (§5А.2), уровень 2 проработан явно.
- [ ] Для каждого объекта задания составлен разбор уровня §5А.5.
- [ ] Каждая деталь объяснима законом §5А.3 (есть причина, почему она здесь).
- [ ] Соблюдён ритм 70/20/10, есть пустые зоны и горячие точки.
- [ ] Добавлено максимально возможное число самостоятельных мелких объектов (мусор, крепёж, следы обитания) — столько, сколько влезает в вес.
- [ ] Ни одна пара повторяющихся объектов не идентична.
- [ ] Фаски есть на всех видимых рёбрах.
- [ ] Roughness варьируется; нет ни одной поверхности с константной шероховатостью.
- [ ] Контактная грязь и контактные тени присутствуют во всех стыках.
- [ ] Крупный план с 30 см выдерживает осмотр (проверить рендером, §2.4).

**Финальный тест:** сделать кроп кадра 1:1 в случайном месте. Если фрагмент выглядит пустым и «чистым» — детализация не сделана.

## §6. ФОТОТЕКСТУРЫ — КЛЮЧЕВОЙ РАЗДЕЛ v2.0

Агент **обязан** сначала искать готовую фототекстуру и только потом моделировать деталь.

### 6.1 Источники (CC0, без авторизации)
- **Poly Haven** — через MCP: `search_polyhaven_assets` / `download_polyhaven_asset`. ~860 текстур, все с реальным размером в мм.
- **ambientCG** — `https://ambientcg.com/api/v2/full_json?type=Material&id=<ID>&include=downloadData`.
- **Poly Pizza** — готовые low-poly модели через MCP.
- Фото пользователя — если приложено, работать с ним по §6.3.

### 6.2 Правильный поиск текстуры через MCP
```
search_polyhaven_assets(
    query       = "weathered brick wall",   # семантический поиск, понимает синонимы
    asset_type  = "textures",
    category    = "Bricks",                 # путь таксономии, не плоский тег
    attributes  = {"condition": "weathered", "surface_use": "wall"},
    min_size_m  = 2.0                       # фильтр по реальному размеру
)
```
- Сначала **`get_polyhaven_categories`** — узнать валидные пути таксономии и схему атрибутов.
- **Смотреть превью до скачивания** (thumbnail ~300 КБ против 24 МБ у 4K-текстуры).
- Скачивать **1K или 2K**, не больше.
- `surface_use` отделяет материал стены от материала пропа — использовать этот фильтр.

### 6.3 Редактирование фототекстуры — что агент обязан уметь

Текстура — это **редактируемый материал**, а не картинка «как есть». Через `execute_blender_code` агент делает:

**A. Вырезание элемента из фото (окно из стены, дверь, пятно)**
- **Alpha-вырез:** маска в шейдере → `Principled BSDF → Alpha`. Дыра без единого полигона.
  ⚠️ **Важно для Blender 4.2+:** режим `Alpha Clip` **удалён**. `blend_method` больше не работает (в Cycles свойство осталось в API, но залипает на `'HASHED'`). Правильно так:
  - поведение Alpha Clip воспроизводится нодой **`Math → Greater Than`** (порог 0.5) перед входом Alpha;
  - режим отрисовки — `material.render_method = 'DITHERED'` (аналог прежнего Alpha Hashed, **предпочтительно**) или `'BLENDED'` (аналог Alpha Blend, только для настоящей полупрозрачности — стекло);
  - тень настраивается не материалом, а на объекте: `obj.visible_shadow = False` при необходимости.
- **Маска по цвету/яркости:** `ColorRamp` / `Color Key` по BaseColor → готовая маска для смешивания.
- **Прямоугольный вырез по UV:** `Texture Coordinate → Mapping → Separate XYZ → Greater Than/Less Than → Math(Multiply)` = маска-прямоугольник в нужных UV-координатах. Ей можно вырезать окно в стене или вклеить другой материал.
- **Геометрический вырез** (если дыра влияет на силуэт): вырезать проём в меше, а рамы и откосы — текстурой.

**B. Удлинение / растягивание стены**
- **Тайлинг:** `Mapping → Scale`. В режиме **POINT** (дефолт Blender) формула: `Scale = размер_поверхности / размер_текстуры`. Стена 8 м и текстура 2 м → Scale по X = 4.0.
  ⚠️ Не переключать Mapping в TEXTURE — это инверсия, и все числа встанут с ног на голову.
- Реальный размер текстуры Poly Haven лежит в свойстве материала **`polyhaven_scale_mm`** — брать его, а не угадывать.
- **Убрать «ковёр» повторов:** смешать два масштаба тайлинга через Noise-маску, либо **Voronoi/hex-тайлинг** со случайным сдвигом и поворотом ячеек.
- **Неравномерное растяжение:** править не Scale целиком, а UV-острова — так тексел-плотность остаётся под контролем.

**C. Стыковка и бесшовность**
- Сделать фото бесшовным: зеркалирование краёв, либо `Musgrave/Noise`-смешение двух сдвинутых копий (`Mapping → Location` +0.5).
- Скрыть шов: наложить decal-плоскость (труба, трещина, растяжка) — классический приём.
- Проверять стык **скриншотом**, а не на веру.

**D. Комбинирование и вариации**
- `Mix Color` двух текстур по Noise/AO-маске → грязь снизу стены, подтёки, выгоревшие участки.
- **Вершинные цвета как маска** — бесплатно по памяти, красится прямо в Blender.
- **Decals** отдельными плоскостями (вывеска, номер дома, граффити, трещина) вместо уникальной текстуры для каждой стены.
- Вариация цвета через `Hue/Saturation` + `Object Info → Random` — одна текстура даёт десять разных зданий.

**E. Атлас и трим-шит (обязательно для набора объектов)**
- **Трим-шит:** один 2K-лист с полосами (базовая панель, карниз, окантовка, вентрешётка, болты, декоративная лента). Высота полос 64/128/256 px — тогда UV-арифметика остаётся целочисленной.
- Текстурирование нового меша превращается в **UV-операцию**, а не в новый проект текстурирования.
- Один трим-шит на весь кит → один материал → один draw call → единая тексел-плотность автоматически.
- Оставить на листе **одну «уникальную» зону** под логотипы и разовые элементы, чтобы не заводить второй материал.
- Атласы дают прирост производительности ~20–40 % в сценах с множеством мелких объектов.

**F. Запечение (bake), когда своя карта неизбежна**
- Собрать высокодетальную версию (или процедурный шейдер) → запечь **Normal / AO / Combined** на low-poly.
- Bake — единственный легальный способ «перенести миллионы полигонов в текстуру»: даёт до 80 % экономии полигонов при сохранении вида.
- После бейка процедурные ноды из файла убрать.

### 6.4 Обязательные правила материалов
- **Principled BSDF.** Число материалов не ограничено — столько, сколько требует детализация.
- BaseColor не чисто чёрный / чисто белый (держать 0.02–0.95).
- Roughness осмысленный и **не константа по всему объекту** — вариация обязательна: камень/бетон 0.7–0.9, дерево 0.6, крашеный металл 0.4, стекло 0.05.
- Metallic — 0 или 1, промежуточное только для переходов.
- Normal strength 0.5–1.5.
- **Ни одного розового (missing) материала.** Ни одного пустого материала. Ни одного материала с `users = 0`.
- Тайлинг обязан соответствовать реальному размеру — кирпич высотой полметра выдаёт непрофессионала мгновенно.

## §7. СВЕТ, ОКРУЖЕНИЕ, ПОДАЧА

### 7.1 HDRI
Через MCP: `search_polyhaven_assets(asset_type="hdris", attributes={"time_of_day": "..."} )` → `download_polyhaven_asset`. Разрешение **1K–2K, не больше** — для просмотра этого достаточно, а 4K HDRI это десятки мегабайт впустую.
Фолбэк без сети: `ShaderNodeTexSky`, тип `MULTIPLE_SCATTERING` (тип `NISHITA` удалён), sun_elevation ~35°, strength 1.0.

### 7.2 Свет
HDRI (strength 0.5–1.5) + **Key** Area ~500–800 W со стороны, + **Fill** 10–25 % от Key, + при необходимости **Rim** для контура. Sun (energy 2–5, angle 0.5°) для резких теней в экстерьере. Больше ламп не нужно.

### 7.3 Цвет
`scene.view_settings.view_transform = 'AgX'`, Look `None` или `Punchy`, экспозиция правится через `view_settings.exposure`, а не мощностью ламп. Нет выжженных бликов, нет чёрных провалов.

### 7.4 Проверка света — через MCP, а не рендером
`get_viewport_screenshot` в режиме Material Preview и Rendered. Агент **смотрит**: читается ли форма, не плоско ли, не пересвечено ли. Отдельный `light_check.py` из v1.3 больше не нужен.

### 7.5 Камера
**Разрешена.** Нужна для стабильных QA-кадров. Перед сдачей — либо удалить, либо оставить одну, выставленную на красивый ракурс (это плюс, а не минус).

### 7.6 Упаковка текстур
- Отдаётся **один `.blend`** → `bpy.ops.file.pack_all()` **обязательно**, иначе у пользователя всё розовое.
- Отдаётся папка проекта → текстуры внешними файлами в `./textures/`, пути **относительные** (`bpy.ops.file.make_paths_relative()`).
- Текстура, лежащая «про запас» без пользователя, **не сохранится** — либо `use_fake_user = True`, либо удалить (предпочтительно удалить).

## §8. ЧТО СТРОИТЬ (сюжетная часть — бывший VERIFICATION)

### 8.1 Шаг A — разбор референса в текст (всегда, до моделинга)
- Фото приложено → выписать стили/культуры: **название + 3–6 ключевых черт** (формы крыш, материалы, цвета, орнамент, пропорции, характерные элементы).
- Фото нет → **самостоятельно** составить такой же список из 3–5 реальных узнаваемых стилей.
- **Сначала текст, потом геометрия.** Всегда.

### 8.2 Шаг B — выбор
Выбрать **1 стиль** (допустимо 2, если это усиливает результат). Объект — **любой из этого стиля**: известная постройка, обычный дом, ворота, пагода, фонтан, маяк, мост, а равно и не-здание: техника, проп, персонаж, природа. Если пользователь назвал объект — делаем его, стиль подбираем под объект.

### 8.3 Шаг C — количество
По умолчанию **1 модель**. Больше — если это раскрывает задачу лучше. Если файл перестаёт открываться — деление на части по §4.5.

### 8.4 Матрица «чего не хватает»

| Чего нет | Что делает агент |
|---|---|
| Фото со стилями | Выбирает 1–2 стиля сам, делает текстовый разбор, работает дальше |
| Фото нечитаемо | Описывает, что разглядел, дополняет общеизвестными чертами |
| Указания, что строить | Выбирает объект сам |
| Размеров | Реальные размеры из жизни в метрах |
| Материалов/цветов | Подбирает под стиль |
| Требования по весу | §4.1 — не ограничен |
| Сети / Poly Haven упал | Процедурные материалы + Sky Texture, в отчёте отметить |
| Вообще ничего, «сделай красиво» | Выбирает всё сам, отчитывается о выборе |

## §10. ГИГИЕНА ФАЙЛА

### 10.1 Чистка перед сдачей
```python
# удалить всё неиспользуемое
bpy.ops.outliner.orphans_purge(do_recursive=True)
# применить трансформы, проверить scale
# удалить: пустые коллекции, объекты вне кадра, дубли материалов (.001),
#          неиспользуемые изображения, лишние UV-слои, вершинные группы, shape keys
bpy.context.preferences.filepaths.save_version = 0    # никаких .blend1
bpy.ops.file.pack_all()
bpy.ops.wm.save_mainfile(compress=True)
```

### 10.2 Не должно быть
`.blend1`, материалов `Material.001`, объектов `Cube.014`, пустых коллекций, невидимой геометрии, датаблоков с `users = 0`, отрицательного или неприменённого scale, объектов вне сцены «для веса».

### 10.3 Именование
`<объект>_<стиль>.blend` — латиница, без пробелов: `greek_villa.blend`, `japanese_gate.blend`.
Объекты: `SM_Wall_A`, `SM_Roof`, `SM_Window_01`. Материалы: `M_Brick_Weathered`. Текстуры: `T_Brick_BC`, `T_Brick_N`, `T_Brick_ORM`.

### 10.4 Выдача — закрытый список форматов

**Допустимо ровно два формата. Список закрыт и расширению не подлежит (§2.6).**

| Формат | Статус | Условие |
|---|---|---|
| `.blend` | **Основной, обязательный** | Всегда. Все текстуры **упакованы внутрь файла** |
| `.glb` | Дополнительный | **Только** по явному запросу, через `export_scene`. Никогда не вместо `.blend` |

**Не принимается ничего другого.** В частности: `.obj`, `.fbx`, `.stl`, `.dae`, `.usd`, `.ply`, `.3ds`, `.gltf` (раздельный), `.abc`, а также `.js`, `.ts`, `.json`, `.py`, `.html`, архивы, скриншоты и текстовые описания вместо модели.

- Никаких архивов, `.blend1`, промежуточных файлов и отдельных папок с текстурами (если не оговорено).
- `.glb` **никогда не заменяет** `.blend` — только сопровождает.
- Отдать `.py`-скрипт «который построит сцену» вместо готового `.blend` — **нарушение ТЗ**, а не альтернативная выдача.

### 10.5 Экспорт в движок (если просят game-ready)
Через MCP: `export_scene` (сцена / выделение / именованные объекты) либо `bpy.ops.export_scene.gltf(...)`.

| Формат | Когда | Настройки |
|---|---|---|
| **GLB** | web, Godot, быстрый обмен, превью | текстуры встроены, +Y up, применить модификаторы |
| **FBX** | Unreal, Unity | Apply Scale: `FBX_SCALE_NONE`, Forward `-Z`, Up `Y`, применить модификаторы |
| **USD** | кино-пайплайны, Omniverse | по запросу |

Обязательно перед экспортом: применить все трансформы и модификаторы, триангулировать (или довериться экспортёру), проверить, что normal map в **OpenGL (`nor_gl`)** для Unity/Blender и **DirectX (`nor_dx`)** для Unreal — иначе рельеф вывернется наизнанку. Материал с `render_method = 'BLENDED'` glTF-экспортёр трактует как Blend, `DITHERED` — как Mask; проверять результат.

## §13. ПОДВОДНЫЕ КАМНИ BLENDER 4.2+ / 5.x (чтобы не наступать)

| # | Грабли | Правильно |
|---|---|---|
| 1 | `blend_method = 'CLIP'` не работает, Alpha Clip удалён в 4.2 | `Math → Greater Than` (0.5) + `render_method = 'DITHERED'` |
| 2 | `mesh.use_auto_smooth` / `auto_smooth_angle` удалены в 4.1 | `bpy.ops.object.shade_smooth_by_angle(angle=radians(35))` |
| 3 | `material.shadow_method` удалён | `obj.visible_shadow` на уровне объекта |
| 4 | Mapping в режиме TEXTURE даёт инверсию тайлинга | Оставлять **POINT** (дефолт). `Scale = поверхность / текстура` |
| 5 | Изображение с `users = 0` молча не сохраняется | `use_fake_user = True` либо (лучше) удалить |
| 6 | Poly Haven называет нормали `nor_gl` / `nor_dx`, а не `normal` | Проверять реальные имена карт при ручном подключении |
| 7 | Скачивание ассета блокирует главный поток — Blender «висит» | Это нормально, ждать. Качать 1–2K, не 4K |
| 8 | `Material.use_nodes` / `World.use_nodes` — deprecated (уйдут в 6.0) | Пользоваться можно, но не строить на этом архитектуру |
| 9 | Движок `EEVEE_NEXT` как enum не существует | Валидные: `BLENDER_EEVEE`, `CYCLES`, `BLENDER_WORKBENCH` |
| 10 | Sky Texture: тип `NISHITA` удалён | `MULTIPLE_SCATTERING` |
| 11 | `bpy.ops` в Edit Mode на плотных мешах — медленно и рискованно | Работать через `bmesh` или numpy `foreach_get/foreach_set` |
| 12 | Smart UV Project на плотной сетке съедает память и время | Разворачивать до уплотнения, на низкополигональной базе |
| 13 | Дубли материалов `.001` после импортов | `orphans_purge` + переиспользование датаблоков |
| 14 | Non-uniform scale ломает нормали и bevel | Применять трансформы (`transform_apply`) |
| 15 | `execute_blender_code` выполняется без отката | Сохраняться до и после каждого крупного шага |

```python
import bpy
def set_tiling(mat_name, surface_m, texture_m):
    """Scale = размер поверхности / реальный размер текстуры."""
    mat = bpy.data.materials[mat_name]
    mp = next(n for n in mat.node_tree.nodes if n.type == 'MAPPING')
    mp.vector_type = 'POINT'                       # НЕ 'TEXTURE' — это инверсия

        surface_m[0] / texture_m[0], surface_m[1] / texture_m[1], 1.0)
```

### C. Alpha-вырез (окно/решётка/листва) — корректно для 4.2+
```python
import bpy
def add_alpha_cutout(mat_name, mask_socket_node, threshold=0.5):
    mat = bpy.data.materials[mat_name]
    nt, nodes, links = mat.node_tree, mat.node_tree.nodes, mat.node_tree.links
    bsdf = nodes["Principled BSDF"]
    gt = nodes.new("ShaderNodeMath")
    gt.operation = 'GREATER_THAN'
    gt.inputs[1].default_value = threshold          # аналог прежнего Alpha Clip
    links.new(mask_socket_node.outputs['Alpha'], gt.inputs[0])
    links.new(gt.outputs[0], bsdf.inputs['Alpha'])
    mat.render_method = 'DITHERED'                  # НЕ blend_method
```

### D. Прямоугольная маска по UV (вырезать зону из фототекстуры)
```python
import bpy
def uv_rect_mask(mat_name, umin, umax, vmin, vmax):
    """Маска-прямоугольник в UV — вклеить другой материал или вырезать проём."""
    nt = bpy.data.materials[mat_name].node_tree
    n, l = nt.nodes, nt.links
    tc  = n.new("ShaderNodeTexCoord")
    sep = n.new("ShaderNodeSeparateXYZ")
    l.new(tc.outputs['UV'], sep.inputs[0])
    def band(idx, lo, hi):
        a = n.new("ShaderNodeMath"); a.operation = 'GREATER_THAN'; a.inputs[1].default_value = lo
        b = n.new("ShaderNodeMath"); b.operation = 'LESS_THAN';    b.inputs[1].default_value = hi
        m = n.new("ShaderNodeMath"); m.operation = 'MULTIPLY'
        l.new(sep.outputs[idx], a.inputs[0]); l.new(sep.outputs[idx], b.inputs[0])
        l.new(a.outputs[0], m.inputs[0]);     l.new(b.outputs[0], m.inputs[1])
        return m
    mu, mv = band(0, umin, umax), band(1, vmin, vmax)
    out = n.new("ShaderNodeMath"); out.operation = 'MULTIPLY'
    l.new(mu.outputs[0], out.inputs[0]); l.new(mv.outputs[0], out.inputs[1])
    return out            # 1 внутри прямоугольника, 0 снаружи
```
