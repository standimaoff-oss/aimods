# Этап 1б: перенос объёмного дыма VolPyro

Статус: **перенос прошёл полный автоматизированный сценарий и просмотр 15 F2-кадров
на llvmpipe**. Частичная alpha.2, не завершение всего этапа 1 и не закрытие всех гейтов ТЗ.
Версия кандидата: `1.0.1-alpha.2`, Minecraft 1.20.1 / Forge 47.4.23 / Java 17.

## Изменения

- Четыре GLSL-файла извлечены **байт-в-байт** из приложенного VolPyro JAR.
  Java-рендерер/симуляция адаптированы к нашему namespace и Forge mappings.
  Атрибуция: [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md).
- Не добавлены предметы, ракеты, рецепты, сущности или расчёты урона донора.
  Существующие ядерки и дроны не удалены. Текущие ракеты пока оставлены до этапа миграции.
- Подключены conventional/nuclear эффекты RealWar, отдельные nuclear эффекты Arsenal,
  BM-21, Tu Bombers, дым от выстрела игрока, собственные дымовые particles,
  дымовая завеса/повреждения/двигатели. [Список 33 файлов с обычными дымовыми
  эмиттерами](../../notes/stage1/volumetric-emitter-paths.txt); дополнительные адаптеры
  FxSystem/BigPuff/TrailFx перенаправляют остальные собственные дымовые эффекты.
- Непрерывные шлейфы донора подключены к RealWar/BM-21 ракетам, Arsenal и Craft
  через ID сущности. Vanilla campfire particles других модов/ванильной игры не заменяются.
- При отключении рендерера или ошибке шейдера новые события используют старые
  эффекты. Исключение отключает только визуальный модуль, не игровую механику.
  Уже подавленный эффект в момент первой ошибки не воспроизводится задним числом.

## Ограничение нагрузки (не обещание FPS)

`config/aiarsenal-volumetric-client.toml`:
- не более 32 обычных объёмов, 96 сегментов шлейфа, 24 объёмов в кадре по умолчанию;
- 8 отдельных ядерных объёмов, 64 отслеживаемых ракет, 4096 ячеек obstacle cache;
- объединение близких повторных дымовых эмиттеров до выделения нового объёма;
- приоритет облака/взрыва выше приоритета декоративных осколков (донор мог вытеснить
  основной взрыв его же осколками);
- для llvmpipe/software: четверть разрешения по каждой оси, максимум 16 шагов луча;
- ядерный взрыв больше не повышает число шагов сверх заданного пользователем бюджета.

Измерение `draw` в QA-логе — CPU-время GL-вызовов, **не аппаратный GPU timer и не FPS**.
Нельзя по нему обещать отсутствие лагов на любом ПК. Модельная оптимизация танков
записана отдельно и в этом этапе не выполнялась.

## OpenGL и жизненный цикл

Снимок/восстановление фактического состояния GL в `try/finally` (через AutoCloseable):
программа, VAO/VBO, read/draw framebuffer, viewport, texture units/bindings, depth,
cull, blend/factors, scissor, clear color. Все изменения состояния внутри прохода
делаются через raw GL, чтобы не рассинхронизировать Minecraft RenderSystem cache.
Освобождение FBO/текстур/шейдеров/буферов при смене мира и resource reload;
повторная попытка компиляции после reload. Учитывается изменение размера окна.

## Проверки

- `python tools/check_volumetric.py`: 5 статических проверок происхождения шейдеров,
  маршрутизации дыма, изоляции серверных регистраций и наличия защит. Не заменяют Minecraft.
- `python tools/check_ppsh.py`: регрессия обеих GLB-моделей ППШ.
- `.github/workflows/volumetric-verify.yml`: build → GameTests → настоящий клиент
  с F2 → сохранение логов/снимков → **draft**, а не автоматическая публикация релиза.
- Неразрушающая серверная команда `/arsenal_visual_test`: отправляет **те же пакеты**,
  что игровые взрывы, для RealWar, Arsenal, BM-21 и Tu Bombers. Требуются права оператора.
  Это тест визуального сетевого пути, не детонация боеприпаса/испытание кратера.
- `/arsenal_fx`: client-only smoke/trail/clear/status/budget/off/on.
  Проверяются компиляция обоих шейдеров, фактические кадры рендера, лимиты очередей,
  очистка и резервный дым при отключённом модуле. off/on не сохраняют config на диск.

Первый прогон [38620040380](https://github.com/standimaoff-oss/aimods/actions/runs/38620040380)
провалился из-за несовместимой сигнатуры `sendSuccess`. Также обнаружено, что default
shell GitHub с `tee` маскировал статус компилятора на шаге build; теперь во всех наших
workflow явно задан `shell: bash` (с `-eo pipefail`). Лог сохранён, не выдан за успешную сборку.

## Осталось в этапе 1

Снайперки (предварительно Мосин ПУ / Kar98k ZF39), C96 / ТТ-33, вкладки эпох,
безопасный вывод ракет и промышленности. Эти задачи **не выполнены этим переносом**.
Отдельно остаются установка JAR в обычный клиент (QA использует userdev), hardware-GPU
и другие shader mods, полный тест смены измерения/resource reload/resize и звуковая приёмка.


Промежуточный прогон [38620706576](https://github.com/standimaoff-oss/aimods/actions/runs/38620706576):
сборка успешна, 149/149 тестов, настоящий клиент скомпилировал оба шейдера, дым при
стрельбе появился. Сценарий остановился после `/arsenal_fx clear`: индекс байтов
из `stat().st_size` ошибочно применялся к Unicode-строке лога. Исправлено чтением
новых байтов через `seek` с последующим UTF-8 decode. Неполные снимки этого прогона
не являются полной визуальной приёмкой. Компиляция шейдеров также перенесена с
первого выстрела на загрузку мира, чтобы не задерживать обработку отпускания ЛКМ.


Прогон [38622620007](https://github.com/standimaoff-oss/aimods/actions/runs/38622620007):
снова успешная сборка и 149/149 GameTests. Ошибка байтового индекса устранена, но
на этот раз команда вообще не попала в журнал клиента: ввод через X11/chat оказался
нестабильным. Добавлен отдельный операторский путь
`/arsenal_visual_test client <эффект> <игрок>`. Клиент принимает его **только** при
явном запуске с `-Daiarsenal.visualQa=true` (автоматически в нашем QA userdev).
Обычный установленный клиент игнорирует пакет; сервер не может этим путём изменить
его локальные настройки дыма. Пакет только PLAY_TO_CLIENT, строка ограничена 16
символами и whitelist. Сетевой протокол Arsenal повышен с 1 до 2: клиент и сервер
нужно обновлять вместе. Это управление тестом; сами взрывы по-прежнему проходят
через прежние игровые пакеты.

Статическая проверка №5 проверяет ограждение QA-моста (opt-in, direction, права).
Она не является проверкой сетевой защиты в настоящем установленном клиенте.

Прогон [38624561045](https://github.com/standimaoff-oss/aimods/actions/runs/38624561045):
сборка и 149/149 GameTests прошли, сценарий не дошёл до FX: короткий импульс ЛКМ
не вызвал выстрел (`Ammo:71`). Теперь сценарий удерживает настоящую ЛКМ до
подтверждения расхода патрона сервером, обязательно отпускает её в `finally` и
сохраняет диагностический F2 при отсутствии выстрела. Проверка расхода патронов
не удалена и состояние боеприпасов не подменяется ради зелёного результата.

Также доработан прогрев рендера: не только compile/link, но один настоящий
прозрачный draw с нулём объёмов при входе в мир. Драйвер может откладывать работу
до первого draw. Прогрев не засчитывается в счётчик кадров с эффектами; последующие
пустые кадры пропускаются **до** GL state capture. После resource/world reset
прогрев повторяется. Это мера против задержки первого выстрела, не замер FPS.

Текущий контрольный прогон:
[38625488573](https://github.com/standimaoff-oss/aimods/actions/runs/38625488573),
исходники `65fb4d2`: **SUCCESS**, 10 мин 14 с. Сборка, 149/149 GameTests,
5 статических проверок переноса + 2 проверки GLB, полный настоящий клиент.

## Результат просмотра и доказательства

Все 15 исходных PNG открыты и просмотрены. Это F2 Minecraft, не Blender-рендеры
и не сгенерированные изображения. [Папка кадров](../../shots/aiarsenal/stage1b/run-38625488573).

| Кадры | Что подтверждено просмотром |
|---|---|
| 01–03 | ППШ в руках, прицеливание через штатный целик, вид спереди от третьего лица |
| 04–05 | Наклон оружия в перезарядке + HUD `reloading`, затем возврат в рабочую позу с Ammo 71 |
| 06 | Отдельный объёмный тёмный дым; мир/рука/HUD продолжают рисоваться |
| 07–08 | Ранний тёмный след обычного взрыва и более позднее поднявшееся серое облако |
| 09–10 | Дымовые облака через игровые пакеты BM-21 и Tu Bombers |
| 11 | Непрерывный светлый наклонный шлейф; верх выходит за пределы кадра |
| 12–13 | Ранняя и более поздняя форма ядерного гриба RealWar |
| 14 | Гриб через отдельный Arsenal NukeFxPacket |
| 15 | Vanilla-подобные резервные дымовые частицы при выключенном модуле |

RCON: `Ammo 71 → 69 → 60 → 71`; удержание/отпускание ЛКМ, R — настоящие X11 inputs,
не прямое изменение Ammo. Во время эффектов: 468 кадров с непустым списком объёмов
(прозрачный прогрев исключён), `FX BUDGET PASS volumes=32 plumes=96`, затем полная
очистка; off/on меняет active false/true. Логи: [client](https://github.com/standimaoff-oss/aimods/blob/4be7c6b9586dd2a761bd425b75d348ab47c245b5/reports/stage1b/run-38625488573/client-latest.log),
[RCON](https://github.com/standimaoff-oss/aimods/blob/4be7c6b9586dd2a761bd425b75d348ab47c245b5/reports/stage1b/run-38625488573/rcon.log), [GameTests](https://github.com/standimaoff-oss/aimods/blob/4be7c6b9586dd2a761bd425b75d348ab47c245b5/reports/stage1b/run-38625488573/gametest-driver.log).

Качество кадров ограничено llvmpipe: четверть разрешения прохода, 16 шагов,
короткая дальность мира (2 чанка). Ядерные эффекты на 100 блоках видны за краем
прорисованного ландшафта; эти кадры **не подтверждают** дальнее terrain occlusion.
Это не демонстрация высокого аппаратного пресета и не обещание FPS. В логе CPU/API
`draw` до ~235 мс у сложных эффектов: software-рендер тяжёлый, несмотря на лимиты.
Стадия огненной вспышки обычного взрыва отдельно кадром не зафиксирована.
