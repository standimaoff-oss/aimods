## Что исправлено

1. **Опасная загрузка данных в OpenGL.** Перед native upload нормализуются pixel-unpack параметры
   и отключается привязанный unpack-PBO; после прохода состояние точно восстанавливается.
   Раньше чужие row/skip/PBO настройки могли заставить драйвер читать за границами нашего буфера.
   Проверены три враждебных состояния с настоящей загрузкой текстуры 64×64.
2. **Ошибки записи чанков.** В предыдущем нагруженном прогоне было пять `ConcurrentModificationException`
   в `IOWorker`. На границе `ChunkStorage.upgradeChunkTag` теперь создаётся глубокая копия NBT,
   чтобы добавление/удаление datafix-контекста не меняло объект, ещё используемый асинхронной записью.
   Новый GameTest вызывает настоящий ChunkStorage. В повторном прогоне серверных ERROR нет;
   после перезапуска установленного сервера подтверждена работа hook: `copies=2554`.
3. **Совместимость с активным shaderpack.** Собственный fullscreen/depth-blit проход отключается,
   используются существующие fallback-эффекты. При выключении пакета объёмный рендер возвращается.
   Это ограниченный совместимый режим, не интеграция нашего raymarch-прохода в Photon.
4. **Сохранение взрывателя авиабомб.** Возраст и задержка вооружения сохраняются в NBT;
   для старых сохранений предусмотрены defaults и ограничения значений.

Причина присланного `nvoglv64.dll` access violation пока **не доказана**. Исправленный OpenGL-дефект
существовал, но для связи с конкретным вылетом нужен `hs_err_pid27388.log` и повтор на Windows/NVIDIA.

Мосина ПУ и мушкета; маска прицела; обычные/ядерные визуальные пакеты; два цикла K off/on.
При активном пакете собственные raw-кадры не добавлялись: **45→45**, затем **83→83**.

**Ограничение стенда:** Linux llvmpipe, `SH_SKYLIGHT=false` — стандартный Photon-пресет превышает
его compute shared memory limit. ZIP пакета не редактировался. Это не сертификация стандартного
пресета, Windows/NVIDIA или аппаратного FPS. R Oculus не переназначался: он действительно
перезагружал шейдеры одновременно с проверкой оружия.
